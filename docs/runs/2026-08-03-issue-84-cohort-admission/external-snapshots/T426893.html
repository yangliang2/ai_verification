Description

Feature summary (what you would like to be able to do and where):
Currently the app does not store viewed images. When you disable images, and click on an image to view, after you close the image and open it again, it will have to be downloaded again. This is not practical neither for the server bandwidth nor for the user experience.

Use case(s) (list the steps that you performed to discover that problem, and describe the actual underlying problem which you want to solve. Do not describe only a solution):
I use the app with images turned off, in order to reduce data usage. When I want to view an image, I tap it, and it loads. When I close the image, I have to download it again to see it upon reopening. In any article, and opening an image that is stored once viewed would mean a faster experience and less data transfer.

Benefits (why should this be implemented?):

  • User does not have to activate data each time they want reopen an image
  • Images are loaded instantly
  • Server gets less requests from users

Comment Actions

When you disable images, and click on an image to view, after you close the image and open it again, it will have to be downloaded again.

There is a bit more nuance to how this works. Images themselves are absolutely cached, at the level of the app's network layer. The problem is that when you view an image in the full-screen gallery, we also make additional API calls to get extra metadata about the image, and these API calls are not cached, which results in preventing the UI from showing the image entirely.
This task can be to make sure that cached images remain viewable in the full-screen gallery, by caching those other API queries more aggressively
