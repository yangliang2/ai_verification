# AI Verification

This context defines the language for an Android behavior-layer verification system that validates AI-generated code changes and measures that verifier with injected defects.

## Language

**Behavior-Layer Defect**:
A defect whose happy path appears correct but fails under Android runtime behavior such as lifecycle changes, navigation state, configuration changes, process death, device state, or concurrency.
_Avoid_: Logic bug, unit-test bug, static defect

**Verification Agent**:
The system that receives a specification, code diff, and buildable source tree, then plans and executes behavior-layer checks and reports remaining risk.
_Avoid_: Test generator, QA script

**Verification Agent Backend**:
The concrete agent surface used to perform verification work, such as Codex CLI using Android CLI and adb tools to inspect code, drive the app, and return structured results.
_Avoid_: LLM provider, model endpoint

**Defect Injection Benchmark**:
A versioned set of source-level Android defects used to measure the Verification Agent's detection capability.
_Avoid_: Test suite, mock bugs

**Goldset**:
A holdout set of real historical behavior-layer defects that were not generated by AI and are used to calibrate the benchmark's credibility.
_Avoid_: Seed tests, examples

**Smoke Slice**:
The smallest end-to-end run that proves the verification chain is executable for one defect without claiming benchmark detection performance.
_Avoid_: M1, full benchmark, acceptance test

**Deterministic Driver**:
A constrained execution driver that performs predetermined device actions to prove an end-to-end chain before the LLM UI driver is ready.
_Avoid_: LLM driver, manual testing

**Android CLI**:
Google's `android` command-line interface for agent-first Android workflows, including environment setup, project metadata, emulator/device management, app deployment, layout/screenshot inspection, Android CLI-supported Journeys, Android docs, and Android skills.
_Avoid_: adb, Android SDK command-line tools, Gradle CLI

**Journey Segment Boundary**:
A controlled boundary between two Android CLI Journey instruction segments where the runner may collect evidence and inject a system event.
_Avoid_: Internal click index, low-level action step

**Run Spec**:
A single-file input contract for one reproducible verification run, containing the host project, APK/package launch metadata, diff/spec inputs, scenario selection, and assertions.
_Avoid_: Benchmark manifest, CLI flags, test case

**Agent-In-The-Loop Execution**:
A verification run where the runner generates structured Journey instructions and checkpoints, while the current coding agent performs UI navigation using Android CLI layout/screenshot tools and adb input.
_Avoid_: Fully unattended execution, manual testing
